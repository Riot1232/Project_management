# T10 — Изучение метода Use Case Points (UCP)

**Дисциплина:** Проектный менеджмент · **Фаза 3** · **Исполнитель:** Алина Недикова  
**Проект A2:** «Система автоматизации внутренних заявок и сервисных запросов».  
**Плановая оценка задачи:** 2 ч 40 мин (не фактическое время).

## 1. Цель и граница задачи

Изучить классический метод **Use Case Points (UCP)** Густава Карнера, проверить его формулы, шкалы, корректирующие факторы и правила перевода результата в трудозатраты, подготовив методическую базу для последующего расчёта T13.

**T10 — подготовка методики, а не измерение проекта A2.** Реальные UAW, UUCW, TCF, ECF, UCP и человеко-часы будут получены в T13 после получения утверждённых T1, T11, T12. Исходный список **11 Use Cases сохраняется без расширения**.

## 2. Назначение метода

UCP позволяет оценивать программные проекты на раннем этапе по типам акторов, сложности сценариев использования, техническим требованиям и условиям предполагаемой команды разработки. Метод предложен Г. Карнером в 1993 году. Условные баллы UCP не тождественны человеко-часам или календарному сроку [1].

## 3. Формулы и шкалы

| Показатель | Формула / правило | Смысл |
|---|---|---|
| UAW | `1×N_simple + 2×N_average + 3×N_complex` | Вес уникальных типов акторов |
| UUCW | `5×UC_simple + 10×UC_average + 15×UC_complex` | Вес 11 Use Cases по числу логических транзакций |
| UUCP | `UAW + UUCW` | Нескорректированный размер |
| TFactor | `Σ(wT_i × rT_i), i=1..13` | Технические факторы, рейтинги 0–5 |
| TCF | `0.6 + 0.01×TFactor` | Поправка технической сложности |
| EFactor | `Σ(wE_i × rE_i), i=1..8` | Условия/компетенции предполагаемой команды |
| ECF | `1.4 − 0.03×EFactor` | Поправка окружения |
| UCP | `UUCP×TCF×ECF` | Скорректированные Use Case Points |
| Effort | `UCP×PF` | Человеко-часы при PF в чел.-ч/UCP |

**Акторы:** Simple — программный интерфейс (1), Average — протокол или текстовый терминал (2), Complex — GUI (3). **Use Cases:** 1–3 логические транзакции — 5 баллов, 4–7 — 10, 8+ — 15. В источнике Карнера интервалы «до 3» и «3–7» пересекаются на числе 3; для учебной схемы принят непротиворечивый порог 4–7 [1, 2].

**Технические факторы T1–T13 (веса по первоисточнику):** `[2, 1, 1, 1, 1, 0.5, 0.5, 2, 1, 1, 1, 1, 1]`. В изложении М. Кона у T2 встречается вес **2**, но в оригинальном документе Карнера — **1**; здесь сохраняется оригинальная версия [1, табл. 3; 2, ч. 2].

**Факторы окружения E1–E8 (порядок в нашем Excel):** опыт процесса +1,5; опыт предметной области +0,5; опыт ООП +1; квалификация ведущего аналитика +0,5; мотивация +1; стабильность требований +2; неполная занятость −1; сложный язык −1. В оригинале Карнера порядок нумерации иной, веса и содержание перечисленных факторов сопоставлены по названиям [1, табл. 4; 2, ч. 2].

## 4. Порядок применения

1. Получить утверждённый реестр акторов и интерфейсов (**T1**).
2. Проверить по всем существующим **11 Use Cases** число транзакций, альтернативы, категории и веса (**T11**).
3. Получить 13 технических и 8 окруженческих рейтингов 0–5 с обоснованиями, включая описание будущей команды (**T12**).
4. Вычислить UAW, UUCW, UUCP, TCF, ECF, UCP (**T13**).
5. Обосновать коэффициент производительности PF или провести сценарный анализ; вычислить человеко-часы (**T13**).
6. Проверить сопоставимость объёма проекта с COSMIC и экспертной оценкой и передать расчёт для T16.

## 5. Ограничения

- Число Use Cases не равно UCP; подсчёт транзакций зависит от согласованного уровня детализации сценариев.
- Транзакция — не клик, SQL-запрос, поле формы или COSMIC-движение E/X/R/W.
- Актор — роль/внешняя система, а не каждый пользователь; одинакового актора нельзя учитывать несколько раз.
- E7 и E8 имеют отрицательные веса; неверный знак ECF искажает вывод.
- Коэффициент 20 чел.-ч/UCP из ранних проектов Карнера — **ориентир, а не универсальный норматив**. При отсутствии собственной истории требуется оговорка и анализ чувствительности.
- UCP и CFP измеряют разные вещи разными методами, напрямую не переводятся друг в друга.

## 6. Результат T10

Подготовлены методический конспект, реестр формул и весов, требования к входным данным T1/T11/T12, проверочный список и Excel-шаблон для T13. **Фактический UCP проекта A2 не рассчитывался**, экспертные оценки коллег не выдумывались. Итоговые выводы о реальной трудоёмкости появятся в T13.
